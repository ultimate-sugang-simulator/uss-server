── 작성 규칙 (이 블록은 산출물에 남기지 마라) ──────────────
1. 이 파일은 가공본이다. 호출자가 mysql로 뽑은 1차 출력을 Read로 읽고 **같은 경로에 덮어쓴다.**
   1차 출력을 따로 보존하거나 별도 파일을 만들지 마라.
2. 수치는 MySQL이 뽑아준 자릿수를 그대로 옮긴다. 임의로 반올림하거나 단위를 바꾸지 마라.
   수집 SQL이 이미 피코초를 ms로 나눠 뒀다. 여기서 단위를 다시 바꾸지 마라.
   대화에서 표로 제시할 때만 읽기 좋게 줄이고, 이 파일에는 원값을 둔다.
3. 행 순서는 1차 출력 그대로(total_ms 내림차순) 둔다. 재정렬하지 마라.
4. **출처**는 Grep으로 확인된 것만 적는다. `{클래스}.{메서드}` 형태로 쓰고,
   확인하지 못했으면 `미상`으로 둔다. 그럴듯한 이름을 지어내지 마라.
   Phase 1에서 확정한 예상 쿼리 목록이 1차 후보다. 목록에 없으면 인터셉터, Hibernate 내부 조회를 의심한다.
5. **하는 일**에는 그 쿼리가 무엇을 읽고 쓰는지만 한 줄로 적는다.
   왜 느린지, 문제인지, 고쳐야 하는지는 쓰지 마라. 이 파일에는 사실만 남는다.
6. `COMMIT` / `ROLLBACK` / `SET autocommit` 같은 트랜잭션 제어문도 빼지 마라. 요청당 트랜잭션 수의 근거다.
   출처 칸에는 `-`, 하는 일 칸에는 `트랜잭션 제어`로 적는다.
7. 쿼리 원문은 1차 출력의 `DIGEST_TEXT` 전문을 그대로 옮긴다. 줄이거나 정규화하지 마라.
   리터럴이 `?`로 치환된 상태 그대로 둔다. 값을 되메우지 마라.
   원문이 `...`로 끝나면 `performance_schema_max_digest_length`에 잘린 것이다.
   그 사실을 해당 행 아래에 한 줄로 명시한다.
8. **직전 상태 대비**는 `{n}` ≥ 1일 때만 쓴다. `{n-1}` 파일을 Read해 같은 출처의 쿼리끼리 비교한다.
   사라진 쿼리와 새로 생긴 쿼리는 그 사실을 명시한다.
9. `읽은행/반환행`(`examined_per_sent`)을 빼지 마라. 하드웨어 독립 증거의 핵심이다.
   `SUM_ROWS_SENT`가 0인 쿼리(쓰기, DDL)는 `-`로 둔다.
