# Git Convention

## 커밋 메시지

형식: `{type}: 커밋 내용(#{이슈번호})`

| type | 용도 | 이슈 라벨 |
|---|---|---|
| feat | 새로운 기능 | `🌼 Feat` |
| hotfix | 긴급 수정 | `🔥 HotFix` |
| fix | 버그 수정 | `🔨 Fix` |
| docs | 문서 변경 | `📚 Docs` |
| test | 테스트 추가/수정 | `🙆🏻‍♂️ Test` |
| cicd | CI/CD 설정 변경 | `🚦 CICD` |
| refactor | 리팩토링 | `🧑🏻‍💻 Refactor` |
| chore | 빌드, 설정 등 기타 | `⚡️ Chore` |
| analysis | 코드 동작 분석, 조사 | `🧪 Analysis` |

> `type`은 커밋 접두사(`{type}:`), 브랜치 접두사(`{type}/`), GitHub 이슈 라벨에 공통으로 쓰인다.
> 라벨 이름은 위 표기 그대로 써야 한다. 이모지 뒤 공백까지 일치해야 `gh issue create --label`이 통과한다.
> 현재 레포에 실제로 등록된 목록은 `gh label list`로 확인한다.

예시: `feat: 강의 검색 기능 구현(#123)`

## 제목 규칙

이슈, PR, 커밋 메시지의 제목에 공통으로 적용한다.

- 40자 이내로, 명사형으로 끊어 쓴다
- 대상을 나열하지 말고 "무엇을 해결했는지"를 남긴다
- 클래스명 나열과 괄호 중첩을 쓰지 않는다
- 한국 개발자가 읽어 바로 이해되는 어휘를 쓴다 (번역투, 불필요한 영어 혼용 금지)

| 지양 | 지향 |
|---|---|
| `refactor: 장바구니/수강신청 검증 로직 분리 및 중복 제거 (CartService/RegistrationService/CourseValidator)` | `refactor: 담기와 신청의 검증 로직 중복 제거` |
| `hotfix: 수강신청 응답에서 현재수강인원(currentEnrollment) 누락 수정(response→dto)` | `hotfix: 수강신청 응답 현재수강인원 누락 수정` |

## 표기 규칙

- 가운데점(`·`)을 쓰지 않고 콤마(`,`)를 쓴다. (예: `이슈·라벨` → `이슈, 라벨`)
- 긴 대시(`—`)를 쓰지 않고 짧은 대시(`-`)를 쓴다. (예: `문제 1 — 유실` → `문제 1 - 유실`)
- 적용 범위는 이슈와 PR의 제목과 본문, 그리고 커밋 메시지다.
- 가운데점은 나열인지 수식인지 모호하고, 긴 대시는 키보드로 바로 입력할 수 없어 손으로 고칠 때 표기가 어긋난다.

## 브랜치 전략

- `main` → `dev` → 각자 개발 브랜치
- main/dev에 직접 커밋하지 마라
- 개발 브랜치 네이밍: `{type}/{이슈번호}-{간단한설명}` (예: `feat/123-bookmark`)
