# Admin

백오피스에서만 쓰는 기능이다. 학생 서비스와 화면도 토큰도 분리돼 있다.

## 관리자 계정

- 관리자 계정을 만드는 API가 없다. 시드 또는 DB 직접 등록으로만 만든다
- 비밀번호는 BCrypt 해시로 저장한다. **`$2a$` 형식만 검증에 통과한다.** `htpasswd`가 만드는 `$2y$`는 거부된다
- 로컬 개발용 계정 하나만 시드로 넣는다. 운영 계정은 레포에 넣지 않는다

## 관리자 인증

- 아이디와 비밀번호로 로그인하면 액세스 토큰과 관리자 이름을 받는다
- **아이디가 없는 경우와 비밀번호가 틀린 경우를 구분하지 않는다.** 같은 실패로 응답해 계정 존재 여부를 감춘다
- 액세스 토큰의 만료는 2시간이다. 리프레시 토큰이 없고 발급된 토큰을 무효화할 수단도 없다
- 재발급은 서명만 검증한다. 만료 여부는 묻지 않으며 재발급 횟수 제한도 없다
- 관리자 토큰은 권한을 담는다. 권한이 관리자가 아니면 백오피스 경로에서 거부된다
- **관리자 토큰과 학생 토큰은 서로의 경로에서 쓸 수 없다.** 서명 키를 공유하므로,
  학생 API가 관리자 토큰을 회원 식별자로 잘못 읽는 것을 막는다
- 로그아웃 경로가 없다. 서버가 무효화할 것이 없어 클라이언트가 토큰을 버리는 것으로 끝난다

### 인증 예외 경로

관리자 로그인과 토큰 재발급만 토큰 없이 호출할 수 있다. 그 밖의 백오피스 경로는 전부 관리자 토큰을 요구한다.

## 표시 학기

- 프론트엔드에 노출할 학년도와 학기다. **강의 데이터와 무관하며 서로를 바꾸지 않는다**
- 항상 1행이며 조회와 변경만 있다. 행이 없으면 실패한다. 없다고 새로 만들지 않는다
- 학년도는 4자리 정수면 통과한다. 현재 연도 기준 범위 제한은 클라이언트 몫이다
- 적재된 강의의 학기와 값이 달라도 정상이다

## 강의 적재 현황

- 적재 학기, 강의 수, 시간표 수, 최근 작업, 진행 중 작업을 함께 내려준다
- **강의 수는 폐강을 포함한다.** 활성 과목 수가 아니다
- 강의가 하나도 없으면 적재 학기가 비어 있다

## 강의 동기화

강의 데이터는 학교 연계 API에서 수집해 적재한다.

### 적재 전략

**전략은 서버가 판정한다.** 관리자는 대상 학기만 고르고 전략을 선택하지 않는다.

| 조건 | 전략 | 결과 |
|---|---|---|
| 적재된 강의가 없음 | 최초 적재 | 전량 생성 |
| 적재 학기 == 대상 학기 | 갱신 | 생성, 수정, 폐강. 장바구니와 수강신청은 보존 |
| 적재 학기 != 대상 학기 | 교체 | 기존 학기의 강의, 시간표, 장바구니, 수강신청을 지우고 전량 생성 |

- 판정 API는 DB를 바꾸지 않으며 매 호출마다 삭제 예정 건수를 다시 센다
- 작업 생성 요청에는 판정 API가 준 전략을 되돌려 보낸다. **서버가 다시 판정해 대조하고, 어긋나면 거부한다.**
  관리자가 확인 화면에서 본 것과 실제 실행될 것이 같음을 보장하기 위해서다
- 진행 중인 작업이 있으면 새 작업을 만들 수 없다. 동시에 도는 작업은 없다

### 실행

- 작업은 비동기로 돈다. 생성 요청은 작업 아이디만 받고 즉시 끝난다
- 진행 단계는 강의 수집, 시간표 수집, 적재 셋이다. **중간 상태는 진행 중 하나뿐이며 미리보기 단계가 없다**
- 진행 상황으로 단계만 알려준다. 백분율, 처리 건수 같은 수치는 내려주지 않는다
- **작업이 도는 동안에도 학생 서비스는 정상 동작한다.** 점검 모드가 없다

### 적재 규칙

- 강의는 학수번호로 대조한다
- 수집되지 않은 강의는 **폐강 상태로 바꾼다. 지우지 않는다.** 장바구니와 수강신청이 강의를 참조한다
- 폐강된 강의가 다시 수집되면 되살리고 상태 변경을 이력에 남긴다
- 시간표는 필드 단위로 비교하지 않고 과목 단위로 통째 교체한다
- **강좌 목록에 없는 학수번호의 시간표는 버린다.** 붙일 강의가 없다
- 정원과 현재 수강인원은 동기화가 건드리지 않는다. 학교가 주지 않는 값이다.
  신규 생성 시 정원은 `course.md`의 기준을 따른다
- **등록되지 않은 코드는 실패가 아니라 경고다.** 해당 강의를 건너뛰고 경고로 남기며,
  경고가 있어도 작업은 성공으로 끝날 수 있다

### 이력

- 작업마다 생성, 수정, 폐강, 경고 항목을 남긴다
- 수정 항목만 어떤 필드가 어떻게 바뀌었는지 함께 남긴다. 경고 항목만 사유를 남긴다
- 건수는 성공한 작업에만 있다. 실패하거나 진행 중이면 비어 있다
- 이력은 작업이 끝나면 바뀌지 않는다

> **알려진 제약**: 학교 연계 API는 등록된 IP에서만 호출된다. 개발 환경에서는 동기화를 실행할 수 없고
> 운영에서만 확인할 수 있다.
