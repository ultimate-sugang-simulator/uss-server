# Service Policy

USS 서비스 정책의 단일 출처다. 정책을 확인할 때 코드를 읽지 않아도 되게 하는 것이 목적이다.
도메인별로 파일을 나눠, 필요한 도메인만 읽고 끝낼 수 있게 한다.

## 작성 규칙

- **담는 것**: 사용자에게 드러나는 규칙과 판정 기준. 성공과 실패 조건, 제한 수치, 산정 기준, 검증 순서, 유효 기간과 초기화 시점, 권한 범위
- **담지 않는 것**: 클래스 구조, 파일 경로, 메서드 시그니처, 쿼리, 트랜잭션 처리 방식
- 위치 표기가 꼭 필요하면 `RegistrationService:60` 수준의 클래스명과 라인까지만 쓴다. 파일 경로는 쓰지 않는다
- 문장은 "무엇을 하면 무엇이 된다" 형태로 쓴다
- 정책이 없는 도메인도 파일을 지우지 말고 `- 별도 정책 없음`으로 남긴다. 지우면 누락과 구분되지 않는다
- 다른 도메인에 이미 적힌 정책을 옮겨 쓰지 마라. `{파일명}을 따른다`로 넘겨라
- 문서와 코드가 어긋나면 이 문서를 기준으로 삼고, 어긋난 사실을 사용자에게 보고한다

## 갱신 규칙

코드 변경으로 위 "담는 것"에 해당하는 규칙이 달라지면 **같은 작업에서** 해당 도메인 파일을 함께 고친다.
`write-plan`은 계획 단계에서 대상 도메인 파일을 읽고, `implement`는 구현 후 바뀐 정책을 반영한다.
도메인이 새로 생기면 파일을 추가하고 아래 목록에 한 줄 넣는다.

## 도메인별 파일

| 파일 | 범위 |
|------|------|
| `auth.md` | 로그인, 토큰, 인증 예외 경로 |
| `member.md` | 회원 정보, 최대 이수 학점 산정, 프로필 |
| `course.md` | 강의 조회와 검색, 정원, 시간표 충돌 판정, 과목 유형 제한 |
| `cart.md` | 장바구니 담기, 조회, 삭제 제한 |
| `registration.md` | 수강신청, 취소, 신청 검증 순서 |
