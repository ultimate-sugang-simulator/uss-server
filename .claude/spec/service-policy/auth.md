# Auth

## 이메일 인증

회원가입에 앞서 이메일 인증을 완료해야 한다. 인증 단위는 이메일 하나당 기록 하나다.

**인증코드 발송**

- 이미 가입된 이메일이면 발송하지 않는다
- 진행 중인 인증(아직 완료되지 않은 기록)이 있으면 발송하지 않는다. 이 경우 재발송을 써야 한다
- 이미 인증이 완료된 이메일이면 발송하지 않는다
- 발송된 코드의 유효 기간은 10분이다

**인증코드 재발송**

- 발송 이력이 없는 이메일은 재발송할 수 없다
- 이미 인증이 완료된 이메일은 재발송할 수 없다
- 재발송은 최대 5회까지다. 5회에 도달하면 더 이상 재발송할 수 없다
- 재발송하면 코드가 새로 발급되고, 실패 횟수가 0으로 초기화되며, 유효 기간이 10분으로 다시 설정된다

**인증코드 검증**

판정 순서는 아래와 같고, 앞선 조건에서 걸리면 뒤는 보지 않는다.

1. 발송 이력이 없으면 실패
2. 이미 인증이 완료되었으면 실패
3. 유효 기간이 지났으면 실패
4. 실패 횟수가 5회 이상이면 실패
5. 코드가 일치하지 않으면 실패 횟수를 1 늘리고 실패

만료 판정이 실패 횟수 판정보다 앞선다. 실패 횟수가 한도에 찬 상태여도 코드가 이미 만료됐다면 만료로 응답한다.
코드 불일치로 늘어난 실패 횟수는 그 요청이 실패해도 유지된다.

코드가 일치하면 인증 완료로 표시한다.

## 회원가입

- 해당 이메일의 인증이 완료되어 있지 않으면 가입할 수 없다
- 이미 가입된 이메일이면 가입할 수 없다
- 비밀번호는 평문으로 저장하지 않는다
- 가입에 성공하면 그 이메일의 인증 기록을 삭제한다. 같은 이메일로 다시 가입하려면 인증을 처음부터 다시 해야 한다

## 로그인

- 학번과 비밀번호로 로그인한다
- 학번에 해당하는 회원이 없으면 실패한다
- 비밀번호가 일치하지 않으면 실패한다
- 성공하면 액세스 토큰과 리프레시 토큰을 함께 발급한다

## 토큰

- 액세스 토큰은 회원 식별자를 담는다. 리프레시 토큰은 회원 식별자를 담지 않는다
- 인증이 필요한 요청은 액세스 토큰과 리프레시 토큰을 **둘 다** 보내야 한다. 하나라도 없으면 실패한다
- 두 토큰 모두 유효해야 요청이 통과한다
- 만료와 위조는 서로 다른 실패로 구분해 응답한다

## 인증 예외 경로

아래 경로만 토큰 없이 호출할 수 있다. 그 밖의 모든 경로는 인증이 필요하다.

- 로그인, 회원가입
- 이메일 인증코드 발송, 재발송, 검증
- API 문서(Swagger) 경로

인증이 필요한 경로를 따로 명시하는 곳은 없다. 예외 경로에 추가하는 것이 곧 공개다.
