# Auth

## 회원가입

- 이메일, 비밀번호, 학번, 이름, 단과대학, 학과, 학년, 학적 상태, 직전 학기 성적을 모두 받아 가입한다
- 이메일이 이미 쓰이고 있으면 가입에 실패한다
- 학과의 소속 단과대학과 보낸 단과대학이 다르면 가입에 실패한다
- 학번은 영문자와 숫자로 이뤄진 20자 이하 문자열이면 통과한다. 자릿수를 고정하지 않는다
- 가입에 성공하면 액세스 토큰을 함께 발급한다
- 이메일 사용 가능 여부는 가입 전에 따로 확인할 수 있다

## 로그인

- 이메일과 비밀번호로 로그인한다. 회원을 식별하는 기준은 이메일이다
- 이메일에 해당하는 회원이 없으면 실패한다
- 비밀번호가 일치하지 않으면 실패한다
- 성공하면 액세스 토큰을 발급한다

학번은 회원 간 중복될 수 있다. 한 학번으로 여러 계정을 만드는 것을 막지 않는다.

## 토큰

- 액세스 토큰은 회원 식별자를 담는다. 리프레시 토큰은 두지 않는다
- 인증이 필요한 요청은 액세스 토큰 하나만 보낸다. 없거나 유효하지 않으면 실패한다
- 만료와 위조는 서로 다른 실패로 구분해 응답한다
- **관리자 토큰으로는 학생 API를 호출할 수 없다.** 두 토큰이 서명 키를 공유하므로,
  관리자 토큰의 식별자를 회원 식별자로 잘못 읽는 것을 막는다. 관리자 토큰 정책은 `admin.md`를 따른다

## 토큰 재발급

- 액세스 토큰을 보내면 새 액세스 토큰을 발급한다. 서명이 유효해야 하며, 만료 여부는 묻지 않는다
- 만료된 토큰도 서명이 유효하면 재발급된다. 서명 검증이 만료 검사보다 먼저 이뤄지므로 위조 토큰은 재발급 단계에서 걸러진다
- 토큰의 회원이 존재하지 않으면 실패한다. 탈퇴한 회원의 토큰이 무기한 연장되는 것을 막는다
- 토큰을 저장하지 않으므로 개별 폐기와 강제 로그아웃은 지원하지 않는다. 유출된 토큰은 만료를 기다리는 것 외에 차단할 수단이 없다

## 인증 예외 경로

아래 경로만 토큰 없이 호출할 수 있다. 그 밖의 모든 경로는 인증이 필요하다.

- 로그인
- 회원가입
- 이메일 중복 검사
- 토큰 재발급
- API 문서(Swagger) 경로
- 모니터링(actuator) 경로
- 관리자 로그인, 관리자 토큰 재발급

백오피스 경로는 학생 토큰 검증을 건너뛰고 관리자 토큰으로 따로 검증한다. 규칙은 `admin.md`를 따른다.

인증이 필요한 경로를 따로 명시하는 곳은 없다. 예외 경로에 추가하는 것이 곧 공개다.

와일드카드로 여는 경로는 기준 경로이거나 그 하위 경로일 때만 열린다. 기준 경로와 접두사만 같은 다른 경로는 열리지 않는다.

CORS 사전 요청(프리플라이트)은 인증 대상이 아니다. 인증보다 먼저 처리되어 응답하며, 예외 경로 목록과 무관하다.
